Thanks again for the kind words and journal tips, it is really appreciated.
 Quick update since we last messaged: I've been heads-down working on Bit-Pop and wanted to share where things stand.
 The biggest thing I've been tackling is strain-level resolution — basically, making Bit-Pop work when two genomes are >99.9% identical (like different strains of the same bacteria). This is exactly the kind of problem you work with in phylogenomics, so I figured you might find it interesting.
I built a fuzzy k-mer matching system that tries to account for small differences between strains. Three approaches:
Fuzzy k-mer — generates all possible k-mer variants with N mismatches and checks each one
Fuzzy seed — similar but works with spaced seeds
Neighborhood — builds a lookup table upfront so fuzzy queries are fast
It's basically a way to say "this k-mer is close enough" instead of "this k-mer must match exactly."
I also ran a CAMI benchmark with 62 microbial genomes (highly similar strains, ~1.4 GB index):
71.6% accuracy on 2,500 read pairs
91.7% mapping rate
Funny story about that — my first run gave me only 1% accuracy. Turns out I had a stupid bug where the genome names in the SAM output didn't match the names in the CAMI ground truth file (the FASTA headers vs. the dataset naming convention). Once I fixed that, accuracy jumped straight to 71.6%.  The remaining accuracy gap is mostly in the evo_* genomes which is exactly what the fuzzy matching is trying to solve.
Important note: none of this is on GitHub yet — I'm still testing everything and it's not ready for prime time. But I wanted to share the progress since it's all connected to what you're working on.
On a side note, I've been drafting the paper for Bioinformatics I'll share it when it's ready and would value your input.

Hi Paul,
 
Quick update on the benchmarking side of the paper.
I decided not to include a direct Kraken2 comparison, for two reasons:
First, a fair comparison isn't currently feasible for me — Kraken2 requires a full NCBI taxonomy dump (~10GB) even when classifying against a small custom genome set, which is beyond my current setup.
Second, and more importantly, I think a direct comparison would actually miss the point of what Bit-Pop is. Kraken2 is built for large-scale classification with institutional infrastructure. Bit-Pop is designed for a different use case — you index only the genomes you care about (megabytes, not gigabytes), the index is permanent and reusable, and classification runs in milliseconds with no external dependencies on laptop. Over time, a user builds their own domain-specific collection of indices. It's lightweight, offline-capable, and practical for field work or clinical settings where a 10GB database simply isn't an option.
So rather than benchmarking against Kraken2, I'll present results on the CAMI Low dataset (80.87% overall accuracy, 1.4GB index) and frame Bit-Pop's contribution around its deployment model rather than raw accuracy competition.
Would love your thoughts on this framing for the manuscript.
